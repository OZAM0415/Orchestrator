# ADR 0003. 공통 실행 정책과 모듈별 입력 검증의 책임

**상태** 채택

## 배경

Manager는 실행할 수 없는 요청을 저장하기 전에 거절해야 한다. Agent도 전달받은 입력을 검사해야 한다. 두 서비스가 텍스트 생성 입력의 규칙을 따로 정의하면 같은 요청을 한쪽만 수락할 수 있다.

## 결정

- **코어**는 요청의 공통 필드를 정규화하고 제한 시간, 최대 시도 횟수, 재시도 간격, 백엔드 지원 여부를 검사한다.
- **버전별 모듈 계약**은 `params`의 필드와 값 범위를 정의한다. 예를 들어 `ai.text.generate`의 `v1` 계약이 `prompt`와 `max_tokens`의 유효성을 결정한다. Manager는 접수 전에 해당 계약을 적용하고, Agent도 실행 전에 같은 계약을 적용한다.
- **Agent**는 추론 서버 준비 상태, 사용 가능한 슬롯, 로컬 실행 제한을 확인한다. 모델에 맞는 요청을 만들고 응답을 해석하는 코드도 실행기에 둔다.

## 검증 사례

빈 `prompt`나 `max_tokens: 0`은 Manager에 제출해도, Agent에 직접 전달해도 거절되어야 한다. 유효한 요청에서 슬롯만 사용 중이라면 입력 오류로 처리하지 않고 같은 Attempt로 대기한다.
