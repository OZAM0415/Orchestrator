# ADR 0001. 시작 응답 유실과 Agent 재시작 시 Attempt 복구

**상태** 채택

## 배경

Agent가 추론을 시작한 직후에 연결이 끊길 수 있다. 이때 새 Attempt를 보내면 같은 추론이 두 번 실행될 수 있다. Manager는 실행 의도를 먼저 저장하고, 기존 시도에 무슨 일이 생겼는지 확인한 뒤 재시도 여부를 결정한다.

## 결정

| 관찰한 사실 | Manager의 다음 동작 | 새 Attempt 생성 |
| --- | --- | --- |
| 시작 요청의 응답을 받지 못했다. | 원래 Agent 인스턴스에서 같은 Attempt ID로 실행을 확인한다. 시작 요청을 다시 보낼 때도 같은 인스턴스, ID, 입력을 사용한다. Agent는 이미 접수한 실행의 참조를 반환한다. | 없음 |
| Agent에 일시적으로 연결할 수 없다. | 현재 Attempt와 세대를 보존하고 통신이 회복되면 다시 확인한다. | 없음 |
| Manager가 재시작됐고 Agent에 기존 실행 기록이 있다. | 저장된 Attempt ID로 상태를 조회한다. 실행 중이면 계속 관찰하고, 종료됐으면 해당 시도에 결과를 반영한다. | 복구 조회 자체로는 없음 |
| 기존 실행을 조회했는데 Agent 인스턴스가 바뀌었거나 해당 실행 기록이 사라졌다. | Attempt를 `LOST`로 기록한다. 취소 의도가 있으면 Job을 `CANCELLED`로 확정한다. 그 외에는 남은 시도 횟수를 확인한다. | 취소 요청이 없고 시도가 남았을 때만 재시도 시각에 생성 |

최초 전달 전의 조회에서 실행 기록이 없는 것은 정상이다. `LOST` 판정은 이미 전달했거나 전달을 시도한 실행을 대조할 때 적용한다. 결과를 저장할 때는 Attempt ID와 세대를 함께 확인한다. 이 검사는 늦게 도착한 결과가 현재 Job을 덮어쓰는 것을 막는다. 외부 시스템에 이미 발생한 부수 효과는 남을 수 있다.

## 검증 사례

Agent가 시작 요청을 접수한 직후 응답만 유실시킨다. 같은 인스턴스에 요청을 다시 보냈을 때 실제 추론 호출은 한 번이어야 한다. 별도 사례로 Agent를 재시작해 기존 실행 기록을 잃게 하면, 원래 Attempt는 `LOST`로 남고 재시도가 허용된 경우에만 다음 세대가 생겨야 한다.
