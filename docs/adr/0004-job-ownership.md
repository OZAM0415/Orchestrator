# ADR 0004. Job 소유권과 멱등성 키의 적용 범위

**상태** 채택

## 배경

여러 사용자가 하나의 `platform-api`를 통해 Manager에 접근한다. Manager의 서비스 토큰만으로는 누가 특정 Job의 결과를 읽거나 실행을 취소할 수 있는지 알 수 없다. 서로 다른 사용자가 같은 멱등성 키를 선택할 수도 있다.

## 결정

1. `platform-api`가 사용자 인증과 소유권 검사를 담당한다. 목록에는 본인 작업만 반환하고, 상세·이력 조회와 취소 전에는 사용자의 접수 기록을 확인한다. 타인의 Job ID와 존재하지 않는 ID에는 동일하게 `404`를 반환한다. Manager는 서비스 토큰으로 호출하는 내부 API다.
2. 사용자 요청의 중복 여부는 `(사용자 ID, Idempotency-Key)` 단위로 판단한다. 같은 사용자가 같은 키와 같은 정규화 입력을 보내면 기존 접수를 반환하고, 같은 키에 다른 입력을 보내면 `409 Conflict`를 반환한다.
3. `platform-api`는 접수 UUID를 먼저 저장하고 Manager에는 `ozam:<접수 UUID>`를 내부 멱등성 키로 전달한다. 응답 유실 시 원래 접수 UUID와 요청을 재사용한다. 이로써 사용자 간 키 충돌을 피하면서 하나의 접수를 같은 Manager Job에 연결할 수 있다.

## 검증 사례

두 사용자가 같은 키로 요청해도 각자 별도의 Job을 받아야 한다. 한 사용자가 다른 사용자의 Job ID로 조회하거나 취소하면 두 요청 모두 `404`로 끝나고 원래 Job 상태는 유지되어야 한다.
